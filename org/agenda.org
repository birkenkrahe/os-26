** DONE Why Linux?

- Linux lets you see what the operating system is doing, instead of
  hiding it behind graphical interfaces.

- The tools you use in Linux make it possible to observe processes,
  memory use, files, and networking directly.

- Linux is the operating system behind most servers, cloud systems,
  and embedded devices, so the skills you learn transfer beyond this
  course.

- Working in Linux helps you understand how programs interact with the
  operating system, not just how to run them.

- Linux supports modern system concepts such as containers and
  resource isolation, which are widely used in industry.

- Learning Linux makes you more confident and independent when working
  with any computing environment.

[Q&A by ChatGPT - extracted exclusively from whiteboard screenshots.]

1. What is the conceptual difference between a *virtual machine (VM)*
   and a *container*?
   #+begin_quote
   A virtual machine virtualizes an entire operating system (including
   its own kernel), while a container shares the host OS kernel and
   isolates applications at the process level.
   #+end_quote

2. Why are platforms like Google Colab or Linux VMs suitable for
   running Linux environments on non-Linux hosts?
   #+begin_quote
   They abstract the underlying hardware by running Linux inside a
   virtualized environment, allowing Linux tools and workflows to run
   independently of the host OS.
   #+end_quote

3. What role does Docker play in the container ecosystem?
   #+begin_quote
   Docker provides tooling to build, distribute, and run containers
   that package applications with their dependencies while sharing the
   host kernel.
   #+end_quote

4. What problem do container *orchestrators* like Kubernetes solve?
   #+begin_quote
   They manage the deployment, scaling, networking, and lifecycle of
   multiple containers across one or more machines.
   #+end_quote

5. What is the role of the *shell* relative to the *kernel*?
   #+begin_quote
   The shell is a user-level program that translates user commands
   into *system calls* handled by the kernel.
   #+end_quote

6. What is a *pipeline* in a Unix-like shell (e.g., =ls | wc -l=)?
   #+begin_quote
   A pipeline connects the output of one command directly to the input
   of another, enabling composition of simple programs.
   #+end_quote

7. Why is RAM described as “fast” compared to non-volatile memory?
   #+begin_quote
   RAM provides low-latency, high-bandwidth access for active
   programs, whereas non-volatile memory is slower but persistent.
   #+end_quote

8. What is the function of the I/O bus in the hardware diagram?
   #+begin_quote
   The I/O bus connects the CPU and memory to peripheral devices such
   as keyboards, displays, storage, and network interfaces.
   #+end_quote

9. In a typical process virtual memory layout, what is the difference
   between the *stack* and the *heap*?
   #+begin_quote
   The stack is used for *function* calls and *local* variables with
   automatic lifetime, while the heap is used for dynamically
   allocated memory with manual or managed lifetime (like *vector*).
   #+end_quote

10. Why can containers generally start faster and use fewer resources
    than virtual machines?
    #+begin_quote
    Because containers do not boot a full OS or run a separate kernel;
    they reuse the host kernel and isolate processes instead.
    #+end_quote

** Review: OS fundamentals I

[Generated by ChatGPT based on the course materials presented.]

1. What is the primary role of an operating system (OS) in a computer
   system?
   #+begin_quote
   To manage hardware resources and provide an abstraction layer for
   applications.
   #+end_quote

2. What happens inside a computer system when a user presses a key and
   a character appears on the screen?
   #+begin_quote
   An application (~bash~) requests resources, the OS kernel schedules
   the CPU and allocates memory, and the CPU executes the task using
   RAM (also involves using the IO/bus, and the display adapter).
   #+end_quote

3. Why does process scheduling become necessary in a multitasking
   system?
   #+begin_quote
   Multiple processes compete for CPU time and must be coordinated by
   the OS. To begin with, you have one process on one CPU by one user,
   and on Linux, you have multiple processes run by multiple CPUs, for
   multiple users.
   #+end_quote

4. What challenges can arise from unclear or simultaneous input
   events?
   #+begin_quote
   Conflicting signals must be interpreted and handled correctly by
   the OS and device drivers, which means the OS needs to decide who
   comes first and who gets how much memory when.
   #+end_quote

5. What is the purpose of separating user mode from kernel mode?
   #+begin_quote
   To prevent user programs from executing privileged operations or
   accessing hardware directly.
   #+end_quote

6. What problem do container technologies aim to address in modern
   computing systems?
   #+begin_quote
   They provide isolated, portable environments for running
   applications. E.g. a docker container with a Python environment.
   #+end_quote

7. How do containers differ from full virtual machines in their use of
   system resources?
   #+begin_quote
   Containers share the host kernel (the machine on which the
   container runs), while virtual machines (VM) run a complete guest
   operating system (on the host machine).
   #+end_quote

8. What does it mean for software to run on “bare metal”?
   #+begin_quote
   It runs directly on hardware without a virtualization layer (like
   an OS - which is a layer of abstraction on top of the hardware).
   #+end_quote

9. Why is version control (e.g. with Git) useful when managing system
   configuration or documentation files?
   #+begin_quote
   It enables tracking changes, collaboration, and reproducibility.
   #+end_quote

10. How does the operating system manage multiple users and
    applications on the same machine?
    #+begin_quote
    The kernel allocates resources and enforces isolation and
    protection by managing the resources automatically.
    #+end_quote

   They are standard input/output data streams used by programs.
   - ~stdin~ = file descriptor 0 (input)
   - ~stdout~ = file descriptor 1 (normal output)
   - ~stderr~ = file descriptor 2 (error output).
   #+end_quote

3. What does the command operator ~>~ do in the shell?
   #+begin_quote
   ~>~ redirects standard output (~stdout~) to a file.
   #+end_quote

4. What if =input.txt= exists when you run =echo "1" > input.txt= ?
   #+begin_quote
   If the file =input= exists it is overwritten; if it does not exist it
   is created.
   #+end_quote

5. How does the operator ~>>~ differ from ~>~ in shell redirection?
   #+begin_quote
   ~>>~ appends output to the end of a file instead of overwriting the
   file.
   #+end_quote

6. How can you redirect *standard error* to a file in the shell?
   #+begin_quote
   Use the file descriptor for stderr (2) with redirection: ~2>
   filename~. This sends error messages to the specified file instead
   of the terminal.
   #+end_quote

   #+begin_src bash :results output :exports both
     ls /nonsense 2> error
     cat error
   #+end_src

7. Why does the command ~ls -l /bin/usr > file.txt~ leave ~file.txt~ empty
   even though an error occurs?
   #+begin_quote
   Because ~>~ redirects only ~stdout~. The error message is sent to
   ~stderr~, which still goes to the terminal unless explicitly
   redirected.
   #+end_quote

8. What does the Unix command ~rev~ do?
   #+begin_quote
   ~rev~ reverses the characters in each line of input. It opens an
   input stream that has to be shut down.
   #+end_quote

9. How can ~rev~ be used inside a shell script?
   #+begin_src bash :results output :exports both

     echo "hello world" | rev

** Review: Expansion I

1. What does *expansion* mean in the context of the Unix shell?
   #+begin_quote
   Expansion is the substitution process the shell performs before
   executing a command, replacing patterns, variables, or expressions
   with their resulting values.
   #+end_quote

2. What does the command =echo *= print?
   #+begin_quote
   The shell performs pathname expansion before running the
   command. The =*= pattern is replaced by all filenames in the current
   directory, so =echo= receives the expanded list instead of the
   literal =*=.
   #+end_quote

3. What happens if a pathname pattern such as =D*= does not match any
   files?
   #+begin_quote
   If no files match the pattern, the shell leaves the pattern
   unchanged and the command prints the literal string =D*=.
   #+end_quote

4. What is =[[:lower:]]=?
   #+begin_quote
   It is a POSIX character class, a standard notation used in patterns
   and regular expressions that represents a set of characters, such
   as all lowercase letters in the current locale (what the shell looks at).
   #+end_quote

   Example:
   #+begin_src bash :results output :exports both
     if [ ! -d test ]; then
         mkdir test
     fi
     cd test
     touch apple Banana cat Dog
     echo [[:upper:]]*
   #+end_src

   #+RESULTS:
   : Banana Dog

5. Why does =echo *= not show hidden files?
   #+begin_quote
   By default, pathname expansion ignores filenames that begin with a
   period, so hidden files are excluded from matches of the =*= pattern.
   #+end_quote

6. Why does the pattern =.*= include both =.= and =..=?
   #+begin_quote
   Because the pattern matches any filename starting with a period,
   and both the current directory (=.=) and the parent directory (=..=)
   satisfy that pattern.
   #+end_quote

7. What does the pattern =.[!.]*= match?
   #+begin_quote
   It matches hidden files that start with a single period but
   excludes =.= and =..= because the second character cannot be another
   period.
   #+end_quote

8. What is *tilde* expansion and what does =echo ~= print?
   #+begin_quote
   Tilde expansion replaces the tilde character with a user's ~$HOME~
   directory. The command =echo ~= prints the current user's home
   directory path. =echo $HOME= does the same thing.
   #+end_quote

   #+begin_src bash :results output :exports both
     echo ~
     echo $HOME
   #+end_src

   #+RESULTS:
   : /home/marcus
   : /home/marcus

9. What is *arithmetic* expansion and what syntax does it use in ~bash~?
   #+begin_quote
   Arithmetic expansion allows the shell to evaluate integer
   arithmetic expressions using the syntax =$((expression))=.
   #+end_quote

   #+begin_src bash :results output :exports both
     echo $((2+2))
   #+end_src

   #+RESULTS:
   : 4

10. What is *brace* expansion and what is it commonly used for?
    #+begin_quote
    Brace expansion generates multiple text strings from a pattern,
    often used to create lists of filenames or directories such as
    numbered sequences or combinations.
    #+end_quote

    #+begin_src bash :results output :exports both
      echo A{1..10}
    #+end_src

    #+RESULTS:
    : A1 A2 A3 A4 A5 A6 A7 A8 A9 A10

    Something to do: use expansion to generate hard passwords

** Review: Expansion II

Why is this "expansion" stuff important?
#+begin_quote
Searching across a huge file system. Accessing environment variables,
and turn input into explicit commands, write general purpose scripts,
automate batch operations, give you full command of the command-line.

The shell is like a saddle to a race horse, and expansion techniques
are like stirrups for the horse.
#+end_quote

1. What is command substitution in the shell and what syntax is
   commonly used?
   #+begin_quote
   Command substitution replaces a command with its output, typically
   using $(command).
   #+end_quote

2. What is the difference between =$(command)= and =`command`=?
   #+begin_quote
   They perform the same function, but $(command) is the modern,
   preferred, and more readable syntax.
   #+end_quote

3. What will =echo $(ls)= output and why?
   #+begin_quote
   Command substitution: outputs list of files in current directory
   because ~ls~ is executed and its output is substituted into ~echo~.
   #+end_quote

4. How does quoting affect command substitution, as in =echo $(cal)= vs
   =echo "$(cal)"=?
   #+begin_quote
   Without quotes, word splitting removes formatting; with quotes,
   formatting (newlines, spacing) is preserved.
   #+end_quote

5. What is word splitting and when does it occur?
   #+begin_quote
   Word splitting divides text into separate arguments based on
   whitespace and occurs on unquoted expansions.
   #+end_quote

6. Which expansions are suppressed inside double quotes?
   #+begin_quote
   Word splitting, pathname expansion, tilde expansion, and brace
   expansion are suppressed.
   #+end_quote

7. Which expansions still occur inside double quotes?
   #+begin_quote
   Parameter expansion, arithmetic expansion, and command substitution
   still occur.
   #+end_quote

8. What is the effect of single quotes on shell expansions?
   #+begin_quote
   Single quotes suppress all expansions, treating everything literally.
   #+end_quote

9. Why does =echo "The total is $100.00"= produce unexpected output?
   #+begin_quote
   =$1= is interpreted as a variable and replaced with an empty string,
   resulting in incorrect output.
   #+end_quote

10. What is the purpose of the escape character =\= in the shell?
    #+begin_quote
    It removes the special meaning of the following character or
    represents control sequences like =\n= or =\t=.
    #+end_quote

** Review from ~chmod~, ~umask~

1. What does the command =chmod 600 foo.txt= do to file permissions?
   #+begin_quote
   It sets read and write permissions for the owner (rw-) and removes
   all permissions for group and others (--- ---).
   #+end_quote

2. How are octal digits related to binary file permissions?
   #+begin_quote
   Each octal digit represents three binary bits, corresponding to
   read (4), write (2), and execute (1) permissions.
   #+end_quote

3. What file mode corresponds to the octal value =775=, and why is it
   commonly used?
   #+begin_quote
   It corresponds to rwxrwxr-x. It is commonly used for directories
   because it allows full access for owner and group, and read/execute
   access for others.
   #+end_quote

4. In symbolic notation, what does =u+x, go=rx= mean?
   #+begin_quote
   It adds execute permission for the user and sets read and execute
   permissions for group and others, removing any other permissions
   they had.
   #+end_quote

5. Why might octal notation be preferred over symbolic notation for
   setting permissions?
   #+begin_quote
   Octal notation is compact, aligns directly with binary
   representation, and is efficient for setting complete permission
   sets in one step ("bulk transactions")
   #+end_quote
